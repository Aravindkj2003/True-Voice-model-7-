## 1. Title
Deepfake Audio Detection System Using Mel-Spectrograms and Transfer Learning (ResNet-18)

---

## 2. Abstract
This project implements a complete deepfake audio detection pipeline that classifies speech clips as Real (Bona-fide) or Fake (Spoof). Audio signals are converted to mel-spectrogram images and passed to a pretrained computer vision backbone (ResNet-18) using transfer learning. The system uses two-stage training (warmup plus fine-tuning), weighted cross-entropy for class imbalance, SpecAugment for regularization, and professional metrics including EER and AUC. In addition to the training/evaluation pipeline, the project includes a deployable web application (Flask backend + React frontend) for real-time audio prediction. The implementation is production-oriented with checkpointing, manifest-based loading, monitoring scripts, and deployment documentation.

---

## 3. Problem Statement
Deepfake speech generated by modern TTS and voice-cloning systems is increasingly realistic and difficult to detect manually. A robust and scalable approach is needed to automatically identify synthetic speech for security, media verification, and digital forensics.

## 9. ML Pipeline Methodology
### 9.1 Input Processing
Audio preprocessing (implemented in src/data_loader.py):
- Load audio with torchaudio
- Resample to 16 kHz
- Convert stereo to mono
- Compute mel-spectrogram:
  - n_mels = 128
  - n_fft = 2048
  - hop_length = 512
  - frequency range = 0 to 8000 Hz
- Convert amplitude to dB scale
- Normalize to [0, 1]
- Resize to 224 x 224
- Convert single-channel spectrogram to 3 channels (RGB-like)
- Apply ImageNet normalization:
  - mean [0.485, 0.456, 0.406]
  - std [0.229, 0.224, 0.225]

### 9.2 Model Architecture
Implemented in src/model.py:
- Backbone: ResNet-18 (default), with optional ResNet-34/ResNet-50 support
- Pretrained ImageNet initialization
- Final head replacement:
  - Dropout
  - Linear(num_features -> 512)
  - ReLU
  - Dropout
  - Linear(512 -> 2)

Binary classes:
- Class 0: Bona-fide (Real)
- Class 1: Spoof (Fake)

### 9.3 Training Strategy
Implemented in src/trainer.py and train.py:
- Two-stage training

Stage 1 (Warmup):
- Epochs: 1 to 5
- Backbone frozen
- Only classifier head optimized
- Learning rate: 1e-4

Stage 2 (Fine-tuning):
- Epochs: 6 to 50
- Entire network unfrozen
- Learning rate: 2e-5

Optimizer and loss:
- AdamW optimizer
- Weighted CrossEntropyLoss (class-balance aware)
- Weight decay: 1e-4

### 9.4 Augmentation
Implemented in src/augmentation.py:
- SpecAugment with random:
  - Frequency masking
  - Time masking
- Default params:
  - freq_mask_param = 30
  - time_mask_param = 40
  - num_freq_masks = 2
  - num_time_masks = 2

## 10. Mathematical Formulation
### 10.1 Weighted Cross-Entropy
For binary classes, weighted loss is:

$$
\mathcal{L} = -\sum_{i=1}^{N} w_{y_i}\log(p_{y_i})
$$

where:
- $w_{y_i}$ is class weight for sample class
- $p_{y_i}$ is predicted probability for true class

### 10.2 Equal Error Rate (EER)
Using ROC-derived operating points:
- FAR: False Alarm Rate
- FNR: False Negative Rate (Miss Rate)

EER is the operating point where FAR and FNR are closest/equal:

$$
\text{EER} = \min_{\tau} |\text{FAR}(\tau) - \text{FNR}(\tau)|
$$

This is included in src/metrics.py along with AUC, accuracy, precision, recall, F1, and confusion matrix components.

## 20. Viva/Presentation Ready Quick Points
- Why mel-spectrograms?
  - Convert temporal audio into structured time-frequency patterns where CNNs perform well.

- Why ResNet-18?
  - Good tradeoff between speed, parameter count, and transfer-learning performance.

- Why two-stage training?
  - Prevents abrupt destruction of pretrained features; improves stable adaptation.

- Why EER in addition to accuracy?
  - EER better reflects security tradeoffs between false alarms and misses.

- Why weighted loss?
  - Reduces bias from class imbalance and improves fairness across classes.
